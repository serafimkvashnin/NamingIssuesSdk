# NamingIssuesSdk

SDK для игр Naming Issues: одна сборка игры работает внутри хаба (iframe, мост через postMessage) и вне его. Пользуются: игры (`src/game.ts`, экспорт по умолчанию) и хаб (`src/host.ts`, `@naming-issues/sdk/host`). Протокол между ними — `src/protocol.ts`.

## Документация — часть изменения

Любое изменение публичного поведения документируется в том же коммите, иначе оно не готово:

- **TSDoc** у каждого экспортируемого символа: что делает, в каком режиме работает (хаб / вне хаба), что возвращает при ошибке или недоступности. У основных функций — `@example`. Это то, что игрок-разработчик видит при наведении в редакторе.
- **README.md**: таблица API, раздел «Проверка игрока на сервере», если меняется пропуск.
- **CHANGELOG.md**: запись под новой версией.

## Как менять

- **Новый метод игры:** функция в `src/game.ts` (с поведением вне хаба) → метод в `HostMethods` (`src/protocol.ts`) → реализация в `src/host.ts` (обычно через опцию `HostOptions`, если нужен хаб) → документация. Хаб после этого обновляет зависимость и передаёт опцию в `createHost`.
- **Совместимость:** игры и хаб обновляются независимо. Не меняй смысл существующих методов и полей — добавляй новые и необязательные. `PROTOCOL_VERSION` поднимается только при несовместимом изменении.
- **Нельзя:** давать игре `initData` хаба или что-то, чем можно действовать в API хаба от имени игрока. Для игр — только пропуск (`token`).

## Выпуск версии

1. Поднять `version` в `package.json`, запись в `CHANGELOG.md`.
2. `npm run build` — `dist/` коммитится (пакет ставится из архива тега без сборки).
3. Коммит, тег `vX.Y.Z`, `git push --tags`.
4. Обновить зависимость в хабе (`NamingIssuesHub`) и в играх: `npm install https://github.com/serafimkvashnin/NamingIssuesSdk/archive/refs/tags/vX.Y.Z.tar.gz`.

Проверка типов: `npx tsc -p tsconfig.json --noEmit`.
